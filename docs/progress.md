## 12. 教学规范

### Day 01–77

以独立编程、程序测试、运行结果和项目实操作为主要验收方式。

不安排独立理论问答、选择题、判断题、填空题或模拟面试。

不提前进行 Java 八股文背诵。

### Day 78–90

集中安排：

- Java 后端理论复习
- 数据结构与算法
- 项目技术讲解
- 项目答辩
- 简历准备
- 模拟技术面试

### 日常教学流程

理论教学 → 示例演示 → 独立编程 → 提交源码 → 静态代码审查 → 修改复验 → 正式验收。

### 课程组织规则

- 一次只进行一节课程。
- 上一节通过后才解锁下一节。
- 正式练习由学习者独立实现。
- 示例程序与正式任务区分。
- 不提前提供正式练习的完整答案。
- 代码审查检查语法、逻辑、边界、输出格式和规范。
- 不再要求编译终端记录。
- 业务测试数量与实际复杂度匹配。
- 历史通过项在局部修改后继续保留。
- 必要时补充针对性测试。
- 正式综合程序必须覆盖当天核心知识点。
- 不重复安排已经通过验收的相同基础任务。

### 文件管理规则

- 每日建立对应的学习目录。
- Java 源码保存于当日 code 目录。
- tasks.md 记录课程及验收结果。
- notes.md 记录理论知识、代码和实际问题。
- docs/progress.md 更新累计进度。
- docs/handoffs/dayXX.md 保存交接信息。
- README.md 同步项目进度。
- 学习记录最终正文采用 Git 归档已完成的预期状态。
- 实际 Git 归档通过真实终端命令验收。
- 不虚构 Git Commit SHA 或远程同步结果。
- 不任意删除历史记录或更改历史验收结论。
